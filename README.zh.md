# dsh-session-cite

把**另一个会话**压缩成一段快照，用引用（mention）的形式带进当前对话；需要细节时再用只读工具 `session_read` 按需继续读取。适用于"把上次排查的过程带进这次对话""让当前会话参考另一个会话的结论"这类场景，而不必手工复制对话内容。

也可以在**消息级**精挑几条原文搬运，或者在**轮次尾部**点转发按钮，把整轮／多轮消息搬到别的会话。

## 功能

- **`/ref` 命令**：在当前会话里执行 `/ref <会话标识>`，插件把目标会话压缩成快照，并生成一个 `dsh-session:` 引用（形如 `@[会话标题](dsh-session:...)`）带进本轮用户消息。
- **两种模式**：`send` 直接发送这条引用消息；`draft` 只把文本放进输入框草稿，由你补充说明后自行发送。
- **`session_read` 只读工具**：快照之外还想要更多内容时，让 Agent 用该工具读取目标会话的后续内容（按字节上限分段读）。
- **消息级转发（`--list` / `--pick`）**：按 seq 挑选具体消息，`--compact` 可先压缩。
- **轮次转发布纽**：每轮尾部一个按钮，把本轮（或多轮）消息转发到其它会话。
- **客户端草稿回填（Web）**：`draft` 模式下，Web 界面会把命令结果自动填进输入框，你补一句话即可发送。

## 安装

1. 把本插件装进目标 profile（以 `web` 为例）：

   ```
   dsh plugin --profile web add link:G:\dsh-dev\plugins\dsh-session-cite
   ```

2. 把下面这一项并入 `~/.dsh/profiles/web/cordis.patch.yml` 的**顶层数组**（该文件本身是数组，直接追加即可，已有条目不要删）：

   ```yaml
   - insert:
       - id: session-cite
         name: 'dsh-session-cite'
         config:
           mode: send
           maxReferences: 3
           guidance: ''
           readBytes: 16384
   ```

   上一步安装插件时通常已经自动合入该条目；只有在 profile 里找不到 `session-cite` 时才需要手工追加（同 id 已存在时直接改它的 `config`，不要重复插入）。仓库内 `cordis.patch.yml` 是 bundle 默认 patch，`examples/cordis.patch.yml` 是带中文注释的安装示例。

3. 重启对应 profile 的会话（或让 Host 重新加载插件），在任意会话里执行 `/ref` 即可。

> 轮次转发面板与消息选择弹窗依赖插件注册的只读路由（`/api/dsh-session-cite/turn-messages`），所以改动 Host 侧代码后需要重启，只刷新页面不够。

## /ref 用法

```
/ref <会话标识>
/ref --draft <会话标识>
/ref --send <会话标识>
```

- `<会话标识>`：用于定位目标会话的关键词（标题、路径、短 id、完整 id 等，按宿主实现匹配）。
- `--send`：无视配置里的 `mode`，强制把引用文本作为本轮用户消息直接发送。
- `--draft`：无视配置里的 `mode`，强制只回填输入框草稿（Web 界面自动回填；其它界面则把文本作为命令结果给出，由你自行复制）。
- 不带标志时按配置项 `mode` 决定。
- 一次最多引用 `maxReferences` 个会话；超出时命令返回错误结果，不发送任何消息。

成功时命令结果的文本形如：

```
@[会话标题](dsh-session:eyJpZCI6InNlc3Npb24tLi4uIn0) 已引用 1 个会话快照
```

## session_read 用法

被引用的会话在快照之后还有内容时，让 Agent 调用只读工具：

- 工具名：`session_read`
- 用途：读取指定会话的会话记录（只读，不修改对方会话，也不向对方会话写入任何事件）
- 单次读取上限：配置项 `readBytes`（默认 16384 字节）

典型对话：

> 你：/ref 上周的排查会话，然后帮我确认那里最后的结论。
> Agent：（调用 session_read 继续读该会话）……结论是 X。

## 配置项

| 配置项 | 类型 | 默认值 | 含义 |
| --- | --- | --- | --- |
| `mode` | `send` \| `draft` | `send` | 默认投递方式：直接发送引用消息，或只回填输入框草稿 |
| `maxReferences` | 整数（1–5） | `3` | 一次 `/ref` 最多引用几个会话 |
| `guidance` | 字符串 | `''` | 追加到快照引用块末尾的自定义指引；空字符串表示不追加 |
| `readBytes` | 整数 | `16384` | `session_read` 单次读取的字节上限 |
| `enableReadTool` | 布尔 | `true` | 是否注册 `session_read` 工具 |
| `pickMaxChars` | 整数 | `4000` | 消息级原文转发的折合字数上限 |
| `pickAsciiWeight` | 数字（0.05–1） | `0.25` | 折合字数里 ASCII 字符的权重 |
| `pickReadBytes` | 整数 | `262144` | 消息级读取预算（字节），防止一次读上千条 |
| `pickKinds` | 数组 | `[user, assistant, tool-result, tool-call, summary]` | 允许转发的类型短名 |

## 失败情形与文案

所有失败都以命令 **error 结果**返回，不写入任何消息、也不改动目标会话：

| 情形 | 结果文本（中文，形如） |
| --- | --- |
| 没给会话标识 | `用法：/ref [--draft\|--send] <会话标识>` |
| 找不到目标会话 | `没有找到与 … 匹配的会话` |
| 命中的会话多于上限 | `命中 N 个候选：…` |
| 引用当前会话自身（会话级） | `不能引用当前会话自身…会话级引用请改为引用另一个会话` |
| 目标会话没有任何可压缩内容 | `目标会话没有可引用的内容` |
| 参数标志无法识别 | `用法：/ref [--draft\|--send] <会话标识>` |

（具体措辞以宿主实现为准；共同点是失败即 error 结果，不会产生半截引用。）

> 会话级自引用被拒绝，但**消息级允许**（`--list` / `--pick`）：那条路径由本插件自己的 pre-step 展开，不经过 dsh 的会话级快照准备，所以「把本会话某几条消息搬进本会话」是可行的。

## draft 模式与降级说明

- **Web 界面**：`--draft` / `mode: draft` 下，命令结果里的引用文本会被客户端自动填入输入框草稿（本插件注册了一个不可见的会话作用域槽，读取本会话最新的 `ref` 命令结果，通过公开的输入动作 `setDraft` 写入）。同一结果只回填一次；如果输入框里已有你自己写的内容，**不会覆盖**，此时命令结果文本仍然可见，可自行复制。
- **其它界面或客户端槽不可用时**：宿主仍然返回含 `dsh-session:` 引用的命令结果文本，客户端不做注入——从结果里复制即可，功能不缺失，只是多一步手工操作。

## 消息级转发（--list / --pick）

会话级引用会把整个会话压缩成快照；消息级转发只搬运你指定的几条消息，适合「把上次那段诊断原样带过来」。

    /ref <会话 id> --list                    # 先看有哪些消息可转发
    /ref <会话 id> --list --limit 50         # 一页 50 条（上限 50）
    /ref <会话 id> --list --before 1180      # 往更早翻页
    /ref <会话 id> --list --after 1251       # 往更新翻页
    /ref <会话 id> --pick 12 13              # 原文转发这两条
    /ref <会话 id> --pick 12 13 --compact    # 交给模型压缩后再转发
    /ref --draft <会话 id> --pick 12         # 只填草稿，不发送

要点：

- `--pick` 用 **seq**（事件序号，纯数字），`--list` 会直接给出。
- `--list` 与 `--pick` 走**原始日志**，所以即使旧消息已被上下文压缩隐藏，依然可以列出并转发。
- 选中 `tool/call` 或 `tool/result` 时自动带上配对项（靠 callId 关联），避免「只有结果不知道调了什么」。
- 未开 `--compact` 时按**折合字数**判定上限：ASCII（英文/代码/空白/标点）按 `pickAsciiWeight` 计（默认 1/4），中文等其余字符按 1 计，阈值是 `pickMaxChars`（默认 4000）。所以同样 4000 的额度，中文约 4000 字、纯英文约 16000 字符——对齐两者在模型侧的实际开销。超限会**报错并同时给出折合字数与原文长度**，不静默截断。
- `--compact` 走一次真实模型调用（消耗配额）；摘要失败一律报错，不静默回退成原文。
- 可转发类型由 `pickKinds` 控制，默认 `[user, assistant, tool-result, tool-call, summary]`。
- `--list` 默认只列 **user / assistant** 对话消息；想看工具往来用 `--kind` 放开，例如 `--kind user assistant tool-call tool-result summary`。`--kind` 零参数即回到默认值，多参数可用空格或逗号分隔，写成未知短名会直接报错。

## 轮次转发面板（按钮）

每轮对话尾部的按钮行末尾有一个「转发」图标（在「在新对话中分支」之后）。它把**本轮**消息搬到另一个会话。

### 单轮转发

1. 点按钮 → 上拉列表选目标会话（与裸 `/ref` 同一个会话数据源、同一套搜索键「标题 · 短 id」；当前会话带「当前」标记，归档会话排在最后并需二次确认）。
2. 弹窗里勾选要转发的消息。默认只选 `user` / `assistant`；顶部按类型的分段按钮点一下全选该类、再点取消。
3. 可填「转发附言」，它作为普通文本行附在引用之后。
4. 底部状态栏实时显示折合字数与上限。超上限时**压缩自动勾选且不可关闭**。
5. 「草稿」/「直接发送」二选一：草稿把引用回填到目标会话输入框，发送则直接提交。

### 多轮转发（勾选）

轮尾转发按钮**右侧**有一个勾选框（默认完全隐藏，鼠标移到按钮组上时用过渡动画滑出）：

- 点它选中**该消息所在的整轮**：该轮所有消息左侧出现 2px 强调色竖线 + 淡背景，首尾行带圆角，视觉上连成一块。
- 已勾选的勾选框常驻显示，鼠标移开也不消失，再点一次取消。
- 一次最多勾选 5 轮（读取成本兜底）。
- 此时点**任意一轮**的转发按钮：面板打开的是「已勾选的轮次 ∪ 按钮所在轮次」的并集，标题形如「转发 3 轮消息 → 「会话名」」，每行带「第 N 轮」标记。
- 没有任何轮次被勾选时，点按钮仍是原来的单轮行为。

> 正在进行的轮次没有尾部按钮，所以它只能作为「按钮所在轮次」被合并进来，不能作为勾选源。

### 数据源：快照 / 原始日志

面板标题右侧有一个「原始日志」开关：

| 来源 | 内容 | 成本 |
| --- | --- | --- |
| 快照（默认） | 客户端 chat 快照，一个工具节点合并了调用与结果 | 零成本，立即可用 |
| 原始日志 | Host 侧读原始事件，`tool-call` 与 `tool-result` 按一次调用合并成一行 | 首次读某轮要解压整份日志 |

- 打开原始日志时，面板先用 `meta` 接口取「本轮共几条、各是什么类型」的骨架（约 0.7 秒），再按 8 条一批填充正文，进度显示「加载中 20/30 条」。
- 加载期间分段按钮、附言、压缩、草稿/发送全部置灰禁用（此时它们指向的仍是快照数据）；只有源开关保持可用——切回快照就等于取消这次读取。
- 开关会记住上次的选择，但**只在本次页面生命周期内**：刷新后回到快照。重新打开面板时还会先探测这一轮是否已在 Host 缓存里，命中才自动沿用原始日志，否则不让你白等。
- 面板里空正文的行（纯工具轮次）会被跳过，并在列表底部提示「另有 N 条内容为空的消息未列出」，与 `--list` 同口径。

### 两条执行路径

| 模式 | 回填/发送的内容 | 原因 |
| --- | --- | --- |
| 草稿 | 一行一个 `dsh-session-message:` 引用（渲染成 chip） | 与会话级引用同款样式，内容在**提交时**由 `agent/pre-step` 展开；草稿保持短小可点删 |
| 直接发送（未压缩） | 完整转发块 | 不依赖 pre-step，链路面最窄 |
| 直接发送（压缩） | 引用 + 压缩标志 | 只有 pre-step 那侧能调模型做摘要 |

压缩真正生效的通道：引用载荷多带 `c:1`，pre-step 见到它就调 `summarizeMessages`；**没有模型路由、调用失败、流为空都退回原文**，不会阻塞会话提交。

### 排障

面板打不开或列表为空时，控制台会输出 `[dsh-session-cite] 转发候选 N 条：seq:kind …`；按钮没进按钮行会输出「转发按钮未能移入按钮行」；多轮勾选安装失败会输出「多轮勾选 DOM 层安装失败」。

## 已知限制

- 引用进消息的是**快照**（压缩后的摘要），不是完整对话；更细的内容要靠 `session_read` 分段读。
- 引用只作用于当前这一轮用户消息，不会与该会话建立长期订阅或联动。
- `session_read` 单次读取受 `readBytes` 限制，超长会话需要多次读取。
- 客户端自动回填只在 Web（`platform: web`）生效；回填是"一次一条命令结果"，不会累计多条引用。
- 不支持把外部会话内容写回被引用的会话（本插件对目标会话严格只读）。
- 冷缓存下首次读某一轮的原始日志，大轮次仍需十几秒——骨架会先出来，但正文要等逐批填充。
- 勾选状态、来源偏好都只存在内存里，刷新即清空。
- 已知上游行为：dsh 的草稿持久化只在会话视图挂载时写一次、发送后不回写，所以「已发送的转发 chip」可能在刷新后重新出现在输入框里。本插件不主动清理（那会误清未发送的草稿）。
